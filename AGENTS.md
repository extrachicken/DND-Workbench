# Инструкции для работы над DND Workbench

## graphify

- `graphify` (`~/.Codex/skills/graphify/SKILL.md`) — any input to knowledge graph.
- Когда пользователь вводит `/graphify`, сначала прочитать установленный навык
  или его инструкции, затем выполнять задачу.

## Git

- В этом проекте работает один агент. Завершённую работу не оставлять только
  локально: проверить, закоммитить, включить в `main` и отправить в `origin`.
  Это постоянное разрешение пользователя от 14 ноября 2026 года; отдельное
  подтверждение обычного коммита и push не требуется.
- Перед изменениями проверить ветку, `git status`, diff и состояние remote.
  Неизвестные изменения сначала изучить; сохранять предыдущую завершённую
  работу отдельным коммитом, не смешивая её с новой задачей.
- Подходящую текущую ветку переиспользовать. Новые ветки: `codex/<задача>`.
  Для последовательной одиночной работы достаточно fast-forward в `main`;
  PR нужен по запросу пользователя, требованиям защиты ветки или для ревью.
- Перед итоговым коммитом выполнить `npm run check` и `git diff --check`;
  для миграций проверить сохранность и откат, для UI — браузерный сценарий.
- Стадировать только просмотренные файлы. Не добавлять личные бэкапы,
  портреты, секреты, временные отчёты, `node_modules` и `dist`.
- До включения в `main` выполнить `git fetch origin`. Не применять force-push,
  destructive reset или перезапись неизвестных коммитов ради чистого статуса.
  При расхождении истории сначала исследовать причину и безопасно согласовать.
- После push проверить совпадение локального и удалённого SHA, результат CI
  и чистый `git status`. Удалять только уже включённые временные ветки.
- Итоговый ответ отличает проверку локально, push, результат CI и размещение
  приложения. Push исходников сам по себе не является публикацией PWA.

## Данные и производительность

- Один экземпляр Dexie и одна текущая модель. Старые схемы нужны только для
  миграции/импорта, а не для параллельной записи или адаптеров UI.
- Старую таблицу удалять только после сохранения снимка в транзакции миграции.
- Не восстанавливать ресурсы при чтении, вычислениях или импорте.
- Оптимизации обосновывать измерениями и проверять сохранность данных;
  настольные результаты не выдавать за проверку на Android.
