# Состояние разработки — 14 ноября 2026

Текущая версия: **0.3.0**. Репозиторий:
[extrachicken/DND-Workbench](https://github.com/extrachicken/DND-Workbench), приватный.

## Завершено к 0.2

- Инженерный план, дизайн-система и проверочный кейс Гу Ченя.
- Адаптивный прототип, игровой учебный лист, ресурсы, кубики, простой инвентарь,
  история, портрет, журнал и резервные копии.
- Список персонажей, выбор, создание и редактирование черновиков с историей.
- Архив и восстановление без удаления записей. Если архивирован последний
  персонаж, приложение предлагает выбрать или восстановить персонажа.
- Раздельное хранение персонажей в рабочем пространстве v2; журнал и единицы
  измерения остаются общими. Старые черновики перенесены в самостоятельные записи.
- Миграция IndexedDB v1 → v2 с сохранением исходного снимка. Старый объект v1
  также остаётся в исходной таблице; новые изменения пишутся только в v2.
- Экспорт v2 и импорт v1/v2. Перед импортом атомарно сохраняется предыдущее
  состояние; если снимок записать нельзя, импорт не выполняется.
- В настройках доступны скачивание исходного снимка и снимка перед последним
  импортом. Внутренние снимки не заменяют внешние резервные копии.
- Редактор черновиков выделен в компонент. Несохранённый текст защищён
  предупреждением при переходе или закрытии страницы; устаревшая редакция
  не перезаписывает изменения другой вкладки.
- Приватный GitHub-репозиторий, README с изображениями, CHANGELOG, CONTRIBUTING,
  описание источников, шаблоны задач и PR, CI, настройки Node и форматирования.

## Разделение данных и единая БД — 0.3

- `CharacterBuild`: имя, происхождение, описание класса, история, портрет
  и известный ручной максимум хитов. Решения по уровням пока не реализованы.
- `RuntimeState`: текущие и временные хиты, остаток ячеек, инвентарь.
- `DerivedStats`: показатели учебного примера, вычисляемые при чтении;
  не попадают в БД или экспорт и не восстанавливают потраченные ресурсы.
  Для черновиков функция возвращает `null`.
- Адаптер `sheetView/updateSheet` удалён. Все экраны используют формат v3.
- Одна БД `dnd-workbench`, один экземпляр Dexie, таблицы `documents` и `recovery`.
  Историческая таблица `workspace` удаляется после сохранения исходного снимка.
  Формат данных — v3; техническая версия Dexie — 4: отдельный шаг нужен,
  чтобы сначала прочитать старую таблицу, затем удалить её.
- Импорт v1/v2/v3, экспорт v3; снимки до миграций и последнего импорта.
  Старые схемы существуют только для чтения архивов и обновления БД.
- Проверка данных при сохранении выполняется один раз. Размер компактного
  JSON обновляется по изменённым полям и хранится с документом атомарно.
  Ограничение 50 МБ действует и при последовательных, и при конкурентных записях.
- Снимки восстановления загружаются при открытии настроек. Журнал группируется
  одним проходом; форматтер дат используется повторно.

Проверки:

- `npm run check`: форматирование, **73 теста**, TypeScript и production-сборка.
- Миграции v1/v2, сохранение всех полей и архива, откат схемы и данных при
  ошибке снимка или исходных данных; повторная инициализация без сброса.
- Проверка расчёта размера на Unicode, экранированных символах, изменении
  массивов, 120 последовательных изменениях и конкурентных транзакциях.
  Превышение лимита отменяет и данные, и счётчик размера.
- Изолированный Chrome: реальная миграция v2; хиты, ячейки, инвентарь,
  портрет и история; создание, редактирование, архив и восстановление черновика;
  журнал, единицы, экспорт v3, импорт всех трёх версий и отказ от ошибочного файла.
- 15 сочетаний экранов и ширин 320/393/1280 px без горизонтального переполнения.
- Production без сети: перезагрузка, изменение ресурсов, запись журнала
  и повторная загрузка с сохранёнными данными. Ошибок JavaScript не обнаружено.
- [Измерения производительности](performance.md): тяжёлая транзакция с
  46,4 МБ данных — медиана 91 мс против 279 мс исходной реализации;
  это настольный Chrome, не результат на Honor X8b.

## Ограничения

- Audit инструментов сборки: 6 записей low/moderate в цепочке Workbox на
  14 ноября 2026. High/critical отсутствуют. Production-зависимости проверяет CI.
  Устранение оставшихся записей — задача до размещения приложения в интернете.
- Нет сервера, синхронизации, HTTPS-размещения или APK. GitHub хранит исходники,
  а не пользовательскую IndexedDB; отправка кода не публикует приложение.
- Правила персонажа в учебном листе частично фиксированы. Созданные черновики
  ещё не превращаются в игровые листы.
- В v3 максимум 101 персонаж вместе с архивом; экспорт/импорт до 50 МБ.
  Каждая запись проверяет, что рабочее пространство ещё можно экспортировать.
  IndexedDB пока читает и записывает весь документ; большие наборы данных
  требуют отдельной проверки на телефоне перед дальнейшим расширением.
- Портрет и инвентарь доступны в учебном листе; редактор черновика пока
  сохраняет имя, происхождение, класс и историю.
- Изменения текста журнала пишутся автоматически, его заголовки — при выходе
  из поля. Полная система мер и веса ещё не реализована.
- Реальное Android-устройство, TalkBack и полный аудит доступности не проверены.

## Запуск после остановки

Прочитать README, этот файл, дизайн и релевантную часть инженерного плана.
Выполнить `npm ci` и `npm run check`. Предпросмотр:
`npm run preview -- --port 4173`. Сохраняйте тот же origin, чтобы видеть прежние
данные браузера.

Сброс недельного лимита не настроен и не является функцией проекта.
