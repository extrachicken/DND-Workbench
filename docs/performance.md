# Производительность и устройство хранения — 0.3

Проверка выполнена 14 ноября 2026 года. Исходная версия для сравнения:
`6d9b1e3` (дизайн и разделение экранов, формат v2).

## Что изменено

- Одна IndexedDB `dnd-workbench` и один экземпляр Dexie. Таблица `documents`
  содержит текущее рабочее пространство; `recovery` содержит снимки и не
  используется как второе рабочее хранилище.
- Старая таблица `workspace` удаляется при миграции. Старые схемы нужны только
  для чтения v1/v2; текущий UI использует v3 напрямую.
- При каждом сохранении была двойная валидация и полная сборка форматированного
  JSON с портретами. Теперь валидация выполняется один раз, размер компактного
  экспорта обновляется по изменившимся полям. Данные и размер записываются
  одной транзакцией. Перед вызовом операции исходные объекты замораживаются,
  чтобы случайная мутация не испортила базу сравнения размера.
- Экспорт и импорт по-прежнему проверяют весь файл. При добавлении/удалении
  элементов массива расчёт размера может сериализовать этот массив целиком;
  частые изменения ресурсов обходятся без повторной сериализации портретов.
- Снимки загружаются только на экране настроек. Журнал группируется одним
  проходом вместо повторной фильтрации каждой кампании; форматтер дат общий.

Миграция данных использует транзакционный callback
[`Version.upgrade`](https://dexie.org/docs/Version/Version.upgrade()).
Отдельный следующий шаг схемы удаляет таблицу после чтения и копирования.
Версия данных и JSON — 3, версия схемы Dexie — 4; это одна база, а не две системы.

## Сравнительный замер транзакций

Настольный macOS, Headless Chrome 157, без ограничения CPU. Настоящая IndexedDB
в отдельном временном профиле; Vite используется для загрузки модулей обеих
версий. Для каждого сценария: 5 прогревочных и 20 измеряемых операций урона.
Замер от вызова `changeWorkspace` до завершения транзакции, без React-рендера.
Тестовые базы удаляются после прогона.

| Сценарий | До: медиана / p95 | После: медиана / p95 |
| --- | --- | --- |
| Один персонаж, без портрета | 0,3 / 0,5 мс | 0,2 / 0,5 мс |
| 16 персонажей, 46,4 МБ | 279,0 / 305,3 мс | 91,3 / 106,1 мс |

Большой набор содержит по 2,9 млн ASCII-символов синтетического base64 в поле
портрета. Это стресс-проверка хранения и сериализации; декодирование настоящих
изображений здесь не измеряется. Разница примерно в три раза относится именно
к этой транзакции. Отдельные прогоны отличаются из-за нагрузки машины и GC.

На минимальном учебном наборе, в изолированном Chrome с окном 393 × 851:

| Перезагрузка без сети до рабочего экрана | 36 мс |

Время клика включает накладные расходы автоматизации Playwright. Показатель
обновляется из live query после записи. Офлайн проверены расход ячейки до нуля,
изменение хитов и заметки, затем перезагрузка и чтение сохранённых данных.
Ошибок JavaScript не обнаружено.

## Как повторить сравнение

Нужны зависимости проекта, установленный Chrome и доступный пакет Playwright.
Playwright не добавлен в обязательные зависимости приложения. В первом терминале:

```sh
npm ci
npm run dev -- --port 5175 --strictPort
```

Во втором, из корня репозитория:

```sh
node scripts/measure-performance.mjs /absolute/path/to/playwright/index.mjs 6d9b1e3
```

Если `playwright` доступен локальному Node, вместо абсолютного пути можно передать
`playwright`. Третий аргумент — конкретная исходная v2-версия для сравнения;
без него измеряется только текущая. Скрипт извлекает три модуля исходной версии
в игнорируемую `tmp/performance-baseline`, не меняя рабочие файлы или ветку.
Результат выводится в терминал и `tmp/performance-results.json`.

## Границы и оставшиеся расходы

- Honor X8b, реальный Android, выгрузка вкладки ОС и TalkBack не проверены.
  Эти числа не доказывают выполнение мобильных ориентиров инженерного плана.
- IndexedDB всё ещё читает и записывает весь рабочий документ. Оптимизация
  убирает лишний JSON, но не стоимость копирования/записи 46 МБ.
- Нет результата для полной будущей библиотеки правил: сейчас это небольшой
  учебный список. Целевой поиск по полному каталогу ещё нельзя оценить.
- Большие архивы и настоящие портреты нужно измерить на телефоне до расширения
  объёма. Если станет мешать запись всего документа, следующий обоснованный
  шаг — отдельные записи сущностей в той же IndexedDB, а не вторая система БД.
- Схемы, снимки и атомарные ограничения сохранены. 73 автоматических теста
  включают миграции с откатом, ресурсы, Unicode-размер, конкурентные изменения
  и отказ от записи архива сверх лимита. Production-аудит npm: 0 уязвимостей.
