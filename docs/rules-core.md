# Основа расчётов D&D 2014

В 0.4.1 добавлены чистые функции `src/rules.ts` и `src/choices.ts`.
Они не обращаются к React, браузеру, сети или БД и не изменяют входные данные.
Это первая часть движка, а не готовый мастер создания персонажа.

## Источники

Сверено 14 ноября 2026 года именно с редакцией 2014:

- [SRD 5.1, Wizards of the Coast](https://media.wizards.com/2023/downloads/dnd/SRD_CC_v5.1.pdf):
  характеристики и проверки, с. 73–75; доспехи, с. 61–62.
  SRD опубликован по [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/).
  Здесь реализованы расчёты, полные тексты документа не включены.
- [Basic Rules 2014: создание и развитие](https://www.dndbeyond.com/sources/dnd/basic-rules-2014/step-by-step-characters):
  таблица мастерства, хиты и выбор одной формулы КД.
- [Basic Rules 2014: характеристики](https://www.dndbeyond.com/sources/dnd/basic-rules-2014/using-ability-scores):
  навыки, пассивные проверки, отмена преимущества помехой, Телосложение.
- [Basic Rules 2014: мультиклассы](https://www.dndbeyond.com/sources/dnd/basic-rules-2014/customization-options):
  мастерство по общему уровню, полная кость хитов только на первом общем уровне,
  отдельные пулы костей разных размеров.
- [PHB errata v3.0, с. 1](https://media.wizards.com/2020/dnd/downloads/PH-Errata.pdf):
  минимальный прирост хитов после первого уровня равен 1.

## Реализованные операции

| Функция | Вход и результат |
| --- | --- |
| `abilityModifier` | Итоговая характеристика 1–30 → округлённый вниз модификатор. Расовые бонусы и черты заново не добавляются. |
| `proficiencyBonus` | Общий уровень 1–20 → мастерство +2…+6. |
| `classLevels` | Упорядоченный список классов каждого уровня → отдельный счётчик каждого класса. |
| `abilityCheck` | Характеристика, общий уровень, уже применимые владения и прибавки → бонус проверки или спасброска. |
| `skillCheck` | Один из 18 навыков; стандартная или явно заменённая характеристика. |
| `passiveCheck` | Активная проверка + 10, отдельные пассивные прибавки, ±5 за преимущество/помеху; одновременно они отменяются. |
| `initiative` | Ловкость и явно переданные прибавки. |
| `armorClass` | Одна выбранная формула, ограничения характеристик, обычный щит и прибавки. |
| `hitPoints` | Решения по хитам каждого уровня и текущее Телосложение → максимум, вклад уровней и максимальные пулы костей. |
| `validateChoices` | Подготовленные требования и решения → список отсутствующих, повторных, недоступных или неверных выборов. |

Числовые проверки, КД и инициатива возвращают `total` и `contributions`:
значение каждой составляющей связано с её источником. Повтор одной обычной
прибавки считается ошибкой входа. Владения обрабатываются иначе: несколько
источников не складываются; компетентность, полное и половинное владение
выбираются в этом порядке. Половина мастерства округляется вниз один раз.
Это внутренний типизированный API: числовые границы и противоречия проверяются,
но произвольный JSON должен сначала проходить схему импорта. Допустимость
самого владения или компетентности определяет обработчик источника.

`ArmorFormula.abilities` задаёт только участвующие характеристики. Для тяжёлого
доспеха список пуст; для среднего ограничение Ловкости +2 сохраняет отрицательный
модификатор. Несовместимая со щитом формула отклоняет его применение.
Подбор доступных формул по экипировке должен выполнять обработчик класса/предмета.

`LevelDecision` — вход расчёта, не вторая хранимая модель персонажа. Каждый
уровень содержит ID класса, кость и решение: `first`, `average`, результат
броска или `null`. У второго класса на первом его уровне используется обычный
прирост. При `null` возвращаются номера незаполненных уровней и `maxHp: null`;
вычисленный частичный максимум не выдаётся за достоверный. Текущее Телосложение
применяется при пересчёте каждого уровня. Временные изменения максимума,
расовые прибавки к хитам и черты вроде Крепкого пока не реализованы.

Требования выбора задают ID, источник, количество, список допустимых ID и,
если нужно, уровень конкретного класса. Они не генерируются из произвольного
текста. Общий уровень 4 у Саванта 3 / Волшебника 1 не открывает выбор Саванта 4.
Самостоятельные обработчики ещё должны подготовить реальные предложения,
проверить предпосылки мультикласса/черт и профиль кампании. Пустой список ошибок
проверяет только переданные требования и не означает полной законности сборки.

## Подключение к приложению

Учебный лист использует ядро для модификаторов, мастерства, инициативы,
Расследования, Внимательности и пассивной Внимательности. Числа и источники
учебных возможностей остаются явно заданным примером из
[кейса Гу Ченя](gu-chen-validation-case.md), не каталогом Саванта.
Замена характеристики и удаление временного владения проверены на уровне
функций; управляющих элементов для этих операций пока нет.

Максимум хитов Гу Ченя остаётся сохранённым ручным значением: история бросков
не установлена. КД 16 и максимум двух ячеек остаются значениями учебного примера.
Расчёт не принимает `RuntimeState`, не лечит персонажа и не восстанавливает
ячейки или кости хитов. Нулевой и неизвестный остаток сохраняются.

Формат рабочего пространства и экспорта остаётся v4, версия Dexie — 5.
Новые типы решений пока не сохраняются, миграция не нужна. Черновик по-прежнему
не превращается в проверенный игровой лист.

## Проверки и следующий шаг

Тесты проверяют границы характеристик и уровней, все ступени мастерства,
дубли владений, половинное владение, замену характеристики, пассивные бонусы,
варианты КД, мультиклассовые хиты, неизвестные решения и неизменность входов.
Отдельно проверены обязательные выборы по уровню класса и повторные пересчёты
учебного листа при остатках ячеек `null`, 0, 1 и 2.

Далее: хранение исходных характеристик и решений по уровням в `CharacterBuild`,
связь с кампанией, небольшой проверенный набор классов/черт и мастер создания
с предварительным просмотром. Потребуются миграция со снимком и сценарий
«создать персонажа → повысить уровень → восстановить архив». Расчёт магии,
все особенности классов и автоматизация полного каталога остаются отдельной
работой; текущие проверки их не подтверждают.
